WHAT CHANGED (LEAST OF THE FIVE)

  • The panel’s recent Premiere-style structure survives intact: header form → estimate → VIDEO / AUDIO / RANGE collapsibles → live preview + transport → queue. This is a re-skin into the shared tokens, not a re-plan.
  • Queue rows get status pills (Done / Running / Queued / Failed) matching the CONVERT page, plus a hover Reveal button — today revealing the file is a right-click-only affordance.
  • Progress moves into a dedicated run row above the queue with frames · fps · ETA and Cancel, instead of a bar floating between status strings.
  • The RANGE section is gone — one dropdown didn’t earn a collapsible. It’s now an “Export in → out only” checkbox in the transport row next to Clear, where in/out points are actually set. Unchecking un-dims the mini-timeline and the estimate re-counts to the full sequence.
  • A small “RENDERING FRAME n / m” pip overlays the preview during a run — the preview already live-updates with rendered frames today; this labels it.

BEHAVIOR KEPT AS-IS

  • Audio-only via Format or toggle: picking “MP3 (audio only)” or switching VIDEO off greys the video section, swaps the estimate and file extension, and shows the audio-only preview state.
  • Match Sequence Settings locks size/fps to the active sequence; export always targets the active sequence (no picker — deliberate).
  • Profile row appears only for ProRes/DNxHR; alpha checkbox enables only for alpha-capable targets; acceleration only for H.264/H.265; quality slider maps to CRF (shown inline now: “High · CRF 19”).
  • Offline-media warning, Pascal NVENC notice, and the HW→CPU fallback dialog all stay.

CODE-LEVEL FLAGS FOUND DURING INVENTORY

  • “Broadcast 1080i” preset is a no-op — it’s in the combo but has no applyPreset case. Dropped from this mockup; either implement or delete in C++.
  • “Add to Queue” never starts the worker — queued jobs only render after a subsequent Export press. Worth a “Start Queue” affordance or auto-start; flagged, not designed in.
  • Smart-render passthrough remains hard-disabled in the backend — correctly has no UI.
  • Sample rate/channels hardcoded 48 kHz stereo — left un-exposed on purpose, one line documents it.
