REMAINING CONFIRMED DEFECTS / SAFETY GAPS
========================================

11. Effects panel can mutate a clip on a locked track [HIGH, CONFIRMED]
Issue:
  EffectsPanel receives only Clip* through setClip() and has no track/read-only
  context. Preset application and other EffectStack mutations can therefore
  modify a clip whose track is locked.
Relevant code:
  src/ui/panels/effects/EffectsPanel.h
  src/ui/panels/effects/EffectsPanel.cpp (setClip and preset actions)
  TimelineWorkspace clip-selection wiring that calls EffectsPanel::setClip.
Proposed fix:
  Pass Track* or an explicit read-only/locked state with the selected clip.
  Disable mutation UI while locked and also fail closed inside every mutation
  handler (preset apply, add, remove, reorder, drop). Inspection and copying
  may remain available.
Side effects:
  Users must unlock the track before changing effects. Existing locked clips
  remain viewable.

12. Finish a complete locked-track mutation audit [HIGH, CONFIRMED FOLLOW-UP]
Issue:
  The main track and drop paths are guarded, but special-feature panels often
  hold direct Clip* pointers and call setters without passing through Track.
  EffectsPanel is a confirmed example. A final audit is needed for every
  user-triggered direct setter and every undo/redo lambda.
Audit scope:
  Effects browser/controls, color grading, properties, graphics, transform
  overlay, tier-list editor, captions, Audio Sync, transitions, relink/replace,
  media-watch replacement, clip enable, speed/duration, and context menus.
Proposed fix:
  Introduce one shared "can mutate clip/track" preflight API and require it at
  UI entry points. Commands should fail closed before partial mutation. Preserve
  the deliberate internal undo/redo bypass only where the command already
  captured a valid unlocked operation.
Side effects:
  Some operations that previously changed only half of a linked/compound edit
  will now reject the entire edit, matching Premiere's locked-track behavior.

13. Resolve remaining shortcut aliases/conflicts only with owner approval
    [MEDIUM, CONFIRMED]
Issue:
  The current source still contains intentional hardcoded aliases and at least
  one historical registry disagreement. Examples to inspect include N
  (workspace snapping versus a registry tool entry), F / Shift+F split
  behavior, the Timeline menu's Ctrl+K split alias, Shift+Backspace ripple
  alias, and fixed shortcuts for new bin/default transition/zoom/export.
Proposed fix:
  Produce a command-by-command matrix: command ID, current registry key,
  hardcoded aliases, focus context, menu label, and actual behavior. Ask the
  owner separately about every proposed mapping change. After approval, model
  legitimate aliases explicitly instead of leaving hidden duplicate routers.
Side effects:

  authorized by this handoff.

14. Complete context-sensitive menu enable/target behavior [MEDIUM, CONFIRMED]
Issue:
  Issue 9 connected the previously inert menu items, but enablement is still
  coarse (mostly "timeline exists"). Premiere enables and targets Cut/Copy/
  Paste/Delete/Split/Ripple based on the active panel, selection type, clipboard,
  locked state, edit point/gap/transition selection, and valid playhead range.
Proposed fix:
  Add central canExecute(command, focusContext) queries. Use the same query for
  menus, toolbar buttons, context menus, and keyboard dispatch. Preserve the
  specialized delete/copy/paste targets for keyframes, masks, effects, graphics,
  Project Bin items, transitions, gaps, and timeline clips.
Side effects:
  Commands will visibly disable when they cannot perform a valid operation,
  instead of silently doing nothing.

16. Prototype CrisperWhisper 2 as an isolated optional worker [HIGH, UPGRADE]
Issue:
  CrisperWhisper 2's fast custom CTranslate2 wheel was Linux x86_64-only during
  the investigation. Windows falls back to PyTorch/Transformers, which is much
  heavier and should not replace the current in-process whisper.cpp path.
Proposed implementation:
  Build an out-of-process worker with a versioned JSON/IPC contract. Keep
  whisper.cpp as the production/default backend until benchmarks and licensing
  pass. The worker must support cancellation, progress, bounded memory, model
  warmup, crash recovery, word timestamps, and deterministic teardown.
Side effects:
  Larger install/model footprint, slower cold start, Python/PyTorch dependency
  management, more VRAM/RAM, and another process to package and update.

17. Run a transcript and sync benchmark before selecting a new model
    [HIGH, UPGRADE]
Benchmark corpus:
  Clean dialogue, noisy dialogue, music under speech, overlapping speakers,
  accents, proper names, short clips, hour-long recordings, silence, retakes,
  clips with non-zero source-in, speed changes, and mixed sample rates.
Measure:
  Word error rate, punctuation/casing, word-boundary timestamp error (median,
  p95, max), drift over long files, dropped/duplicated words at chunk seams,
  diarization/speaker usefulness, Audio Sync alignment accuracy, real-time
  factor, cold/warm startup, RAM, VRAM, GPU utilization, and cancellation time.
Acceptance requirement:
  The replacement must materially improve timestamp/sync accuracy, not merely
  transcript wording. Store golden expected timing data and make the benchmark
  repeatable.

18. Add a backend capability contract and graceful model diagnostics
    [MEDIUM, UPGRADE]
Issue:

Proposed fix:
  Add explicit backend capabilities and structured errors. The UI should show
  unavailable model/runtime/license conditions before starting, distinguish
  cancellation from failure, and never treat an empty stub result as success.
Side effects:
  Requires a small API change across Transcriber, Captions, and Audio Sync.

19. Improve caption quality-control and transcript editing [MEDIUM, UPGRADE]

EXPORT / RENDERING FOLLOW-UP
============================

31. Optimize strict export verification without weakening it
    [MEDIUM, UPGRADE]
Current state:
  Export now stages output, performs strict payload checks, then fully decodes
  and validates count/dimensions/CFR timestamps before atomic publication.
Issue:
  The validation adds one complete decode pass and extra same-volume disk use.
Proposed fix:
  Profile first. Parallelize safe validation work, reuse encoder accounting,
  expose validation progress, estimate temporary disk requirements, and clean
  abandoned staging files on startup. Retain the final independent decode for
  formats where packet accounting cannot prove integrity.
Side effects:
  Optimization must never reintroduce publication of truncated or mis-timed
  output.

32. Reintroduce smart rendering/passthrough only behind strict eligibility
    [LOW/MEDIUM, UPGRADE]
Current state:
  Smart passthrough is disabled for correctness.
Proposed fix:
  Add a proven eligibility graph covering codec/profile/level, resolution,
  frame rate/time base, color metadata, GOP/edit boundaries, audio parameters,
  effects/transforms/transitions, alpha, speed, and exact timestamp continuity.
  Fall back to full render for any uncertainty and run the same final integrity
  validation.
Side effects:
  Large correctness surface; performance benefit is substantial only for
  eligible media.

33. Unify preview and export rendering cores [MEDIUM, ARCHITECTURE]
Finding:

Side effects:
  High regression risk. Migrate one layer type at a time and compare frame
