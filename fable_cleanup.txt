How this report was produced: every .cpp on disk was diffed against the
explicit CMake source lists; every header was checked for inclusion anywhere;
an 8-line normalized-window hash scan was run across all 637 files to find
copy-paste duplication mechanically; and the decode/cache/playback/export
stack was read against Premiere Pro's known architecture (importer model,
Mercury 32-bit float pipeline, proxy/preview-render workflow, audio conform).

Verdict up front: the codebase is in better shape than most projects this
size — explicit CMake lists, a unified preview/export render path, real
tests (654 green), three-tier caching, hardware decode AND encode with
multi-vendor fallback. The problems are concentrated in three places:

  1. UI "god classes" split across dozens of translation units instead of
     decomposed into real classes (TimelineWorkspace = 21 files).
  2. Copy-paste duplication in predictable clusters (monitors, export
     encoders, wiring files, serialization helpers).
  3. The media pipeline is 8-bit BGRA with hardcoded BT.709 color, which is
     the single biggest gap vs Premiere for pro-format ambitions.

3.1  THE GOD-CLASS-BY-TRANSLATION-UNIT PATTERN (biggest structural issue)
     Several huge classes are "modularized" by splitting METHOD DEFINITIONS
     across many .cpp files while remaining one class with one giant header:

       TimelineWorkspace : 21 .cpp files, 635-line header, ~106 methods
       TimelinePanel     : 15 .cpp files, 682-line header
       MediaPool         :  9 .cpp files (+ MediaPoolPrefetchInternal.h)
       MainWindow        : 10 .cpp files
       ShotComposer      :  6 .cpp files
       EffectControlsPanel: 4 .cpp files

     This hides the problem instead of fixing it: every file still sees every
     member, anything can mutate anything, and the wiring files (2.1) show
     the result. Since aggressive restructuring is approved, decompose by
     RESPONSIBILITY into real classes:

     TimelineWorkspace → keep as a thin composition root that owns:
       - PanelFactory        (PanelsCreate)
       - PlaybackBindings    (PanelsPlayback, transport wiring)
       - SelectionBindings   (PanelsWiringClipSelection)
       - DropController      (PanelsWiringMediaDrop / EffectDrop / Nest)
       - OverlayController   (Overlay, WiringTransformOverlay, WiringViewport)
       - CompositeBridge     (Composite, Spine)
       - EditCommandRouter   (EditCommands, Keys, PanelsShortcuts)
     Each binder is a small QObject taking only the collaborators it needs.
     Mechanical migration: move the member variables each binder touches,
     leave accessors on TimelineWorkspace during transition.

     MainWindowProject*.cpp (4 files) → ProjectController class (open/save/
     recent/recovery already half-isolated in MainWindowRecovery.cpp).

     MediaPool: acceptable as a facade, but the prefetch engine
     (MediaPoolPrefetch*.cpp, 6 files incl. the 1247-line ConvertGpu) wants
     to be its own PrefetchEngine class — it already has a private internal
     header, which is the tell.

     Naming bug while you're there: the wiring files inconsistently use two
     prefixes — TimelineWorkspaceWiring* AND TimelineWorkspacePanelsWiring*.

What you ALREADY match Premiere on (don't let cleanup regress these):
  + HW decode chain with fallback: NVDEC/CUDA → D3D11VA → QSV → SW
    (VideoDecoderInit.cpp:618+), shared hw device contexts.
  + HW encode multi-vendor: NVENC → QSV → AMF (Encoder.cpp:61-77), plus
    AV1/ProRes/DNxHR/image-sequence export and MP4/MOV/MKV muxing.
  + Three-tier cache: RAM FrameCache (50% RAM) + GpuTextureCache (60% VRAM)
    + persistent DiskFrameCache — Premiere's media cache analog, plus
    adaptive budgets (PerformanceProfile).
  + Latest-wins scrub coalescing on a producer thread (FrameProducer
    m_pendingScrub) — correct architecture for responsive scrubbing.
  + JKL shuttle with speed doubling, loop, edit-point navigation.
  + Resolution tiers (Full/Half/Quarter ≈ Premiere playback resolution).
  + Smart render passthrough with keyframe-boundary gating, all 5 codecs.
  + Unified preview/export compositor (Premiere parity; many NLEs fail this).
  + Disk-persisted waveform peaks (≈ Premiere .pek).
  + PortAudio/WASAPI audio engine, A/V sync clock, baked audio FX windows.
  + VFR *detection*, packed-alpha pipeline, interpret-footage (fps override).

GAPS, ranked by impact on your stated goals (scrub smoothness, broad
formats, export quality):

4.1  COLOR MANAGEMENT IS HARDCODED BT.709            ** top format gap **
     ConvertDecodedFrame.cpp:102 forces SWS_CS_ITU709, limited range, for
     EVERY source. Consequences today:
       - SD / BT.601 content (old web video, DVDs): visibly wrong colors.
       - BT.2020/HDR (PQ/HLG phone + camera footage, very common from
         yt-dlp): wrong primaries, no tone-map — washed out or oversaturated.
       - Full-range JPEG/MJPEG sources: crushed levels.
     Premiere reads colr atoms / stream colorspace per clip and converts
     through a managed pipeline. FIX (incremental):
       a) Read AVFrame/stream colorspace+range+primaries+trc in
          VideoDecoderInit; store in VideoStreamInfo.
       b) Pass them to sws_setColorspaceDetails per-source instead of the
          constant (one call site thanks to the unified ConvertDecodedFrame
          — the unification you already did makes this cheap).
       c) Later: HDR→SDR tone-map (zscale or a GPU shader) for PQ/HLG.

4.2  8-BIT BGRA PIPELINE END-TO-END                  ** top quality gap **
     CachedFrame = std::vector<uint8_t> BGRA (FrameCache.h:133). 10-bit
     HEVC (P010), 12-bit ProRes 4444, banding-sensitive gradients — all
     quantized to 8-bit at convert time, then composited, then re-encoded.
     Premiere composites in 32-bit float on GPU (Mercury). You don't need
     float32 everywhere; the pragmatic path:
       - GPU path: extend Nv12Converter to output RGBA16F (P010 and
         yuva444p12 converters already exist and are throwing away depth at
         the final step), composite in 16F, dither down only at the
         viewport/encoder boundary.
       - CPU/cache fallback stays 8-bit; CachedFrame grows a format field
         (it already has 'origin', 'tier' — add 'depth').
     Big job; schedule after the structural cleanup, but every pro-format
     ambition (ProRes RAW, DNxHR HQX, HDR delivery) is gated on it.

4.3  VFR DETECTED BUT IGNORED                        ** top robustness gap **
     VideoDecoderInit.cpp:489 sets m_info.isVFR — and that is the ONLY
     reference in the tree; nothing reads it. Frame lookup is constant-fps
     math (VideoFrameMapping::mapTickToSourceFrame). On VFR sources (phone
     recordings, OBS/game captures, most yt-dlp output — your stated
     intake!) audio drifts against video over minutes and frame-stepping
     stutters. Premiere offers PTS-true mapping / conform. FIX options:
       a) Honest minimum: surface a "VFR detected — may drift" badge in the
          project bin + InterpretFootageDialog.
       b) Real fix: when isVFR, build a PTS index at open (you already
          decode-scan for keyframes) and map tick→frame through it inside
          mapTickToSourceFrame — the unified mapping function means ONE
          call site again.
       c) Premiere-style optional conform-to-CFR on import (you already
          have the conversion pipeline infrastructure in core/convert).

4.4  SINGLE AUDIO STREAM PER FILE
     VideoDecoderInit.cpp:437 takes the FIRST audio stream;
     AudioFile.cpp:853 takes av_find_best_stream. Multicam interviews,
     camera files with scratch+lav tracks, OBS multi-track recordings: the
     other streams are unreachable. Premiere exposes all streams with
     channel mapping. FIX: enumerate audio streams into VideoStreamInfo;
     UI affordance = stream picker in InterpretFootageDialog (or clip
     right-click → Audio Stream). Storage format bump for the choice.

4.5  LINEAR-INTERPOLATION RESAMPLER IN THE AUDIO PATH
     AudioFile.cpp:241 resampleInterleavedLinear() — hand-rolled linear
     interp used at three real fetch sites (lines 584, 611, 698) even
     though swresample is already linked and used elsewhere in the same
     file. Linear interp = audible HF rolloff + aliasing on 44.1→48k
     conversions. FIX: route those three sites through the existing swrCtx
     (or soxr engine flag). Small, high-value, isolated.

4.6  NO PREVIEW-RENDER / BACKGROUND-RENDER SYSTEM
     The render-bar UI stub exists (1.7) but there is no render-in-to-out,
     no preview-file cache keyed to timeline segments, no background
     rendering. Your DiskFrameCache partially substitutes (it persists
     composited?? — no: it persists DECODED source frames). For heavy
     sections (stacked effects, 4K long-GOP, glitch macros) Premiere users
     render previews and export can even reuse them. ROADMAP ITEM, not
     cleanup: a SegmentRenderCache that (a) hashes timeline segment state
     (clip ids + effect params + transitions — you already have
     FrameSignature infrastructure for hashing!), (b) renders segments
     in idle time through the existing compositor, (c) feeds the render
     bar, (d) lets export consume green segments. This is the single
     biggest playback-smoothness feature you're missing; everything else
     in the realtime path is already sound.

4.7  NO PROXY WORKFLOW
     Resolution tiers downscale at decode time, but heavy codecs still pay
     full decode cost (your own ProRes-at-1/2-res workaround is the
     symptom). Premiere: attach/generate proxies, toggle. You already have
     every ingredient: conversion encoders, a converted-assets directory
     convention (assets/converted), MediaPool handle indirection. A
     ProxyManager that generates (e.g. half-res NVENC H.264 AQ or DNxHR LB)
     and lets MediaPool transparently swap source paths per handle would
     mostly reuse existing code. Lower priority than 4.6 given tiers exist.

4.8  IMAGE FORMAT INTAKE IS NARROW
     MediaPoolOpen.cpp:117: imgExts = {.png, .jpg, .jpeg}. No TIFF, WebP,
     EXR/DPX (pro), GIF, BMP, AVIF — and no NUMBERED IMAGE SEQUENCE import
     (export-side ImageSequence exists, import doesn't). FFmpeg can decode
     most of these already — for several formats it may be a whitelist
     problem, not a decoder problem. Cheap win: route unknown image
     extensions through the FFmpeg probe before rejecting.

4.9  SMALLER PREMIERE-PARITY NOTES (file under "later"):
     - Growing-file refresh (OBS recordings open mid-write): not supported.
     - Audio conform: windowed decode w/ 16s lookahead is fine for editing,
       but long-timeline random seeks rebuild windows; Premiere's
       conform-once-to-CFA avoids that. Revisit only if audio scrub feels
       laggy on hour-long timelines.
     - Timecode: no start-TC offset / drop-frame display (matters for
       broadcast interchange only).
     - Field order / interlace handling: absent; fine unless old TV content
       is in scope ("anything from the internet" occasionally is).
